# Correction & Mistake Log

Entries are appended here whenever the user corrects the AI or the AI self-identifies a deviation from the blueprint or the user's intent. Empty at project start — this file grows over time.

[2026-09-22] - `StateProvider` from `flutter_riverpod: ^3.4.3` is not exported from the main `flutter_riverpod.dart` barrel anymore - `import 'package:flutter_riverpod/legacy.dart';` is required to use it - When adding a simple `StateProvider<T>` on Riverpod 3.x, import `package:flutter_riverpod/legacy.dart` explicitly instead of assuming the default import covers it; `flutter analyze` will flag the missing symbol immediately if forgotten.

[2026-09-22] - Two Claude Code sessions were editing this same project concurrently (both building the dashboard restyle + floating nav bar independently), which briefly caused overlapping/duplicate files (`features/budget/` vs `features/budgets/`) and a shared dev server port conflict on 8788 - Before assuming a file changed unexpectedly is corruption, check whether another active session/dev-server is running on the same project and reconcile rather than overwrite - When multiple sessions touch the same Flutter template project at once, expect duplicate scaffolding for the same feature and de-dupe by keeping whichever is already wired into the router/shell.

[2026-09-22] - Ran `taskkill /F /IM chrome.exe /T` on Windows to stop a verification `flutter run -d chrome` instance, which kills every Chrome process on the machine by name (the user's own browser windows, other sessions' Chrome instances) instead of just the one started for verification - Stop a specific dev-server browser by PID (e.g. resolve the PID via `Get-NetTCPConnection -LocalPort <port>` or the `flutter run` process itself, then `Stop-Process -Id <pid>`) or let the harness's own preview/task-stop tooling tear it down, never a blanket `taskkill /IM chrome.exe` - On Windows, any `taskkill`/`Stop-Process` by image name instead of PID is a destructive, unscoped action; always scope kills to the specific PID you started.

[2026-09-22] - Used `ref.watch(someStreamProvider).valueOrNull` when rebuilding the budget screen (`lib/features/budget/presentation/budget_screen.dart`, `lib/features/accounts/presentation/account_providers.dart`) and `flutter analyze` failed with `undefined_getter` - `riverpod: 3.4.3` (installed via `flutter_riverpod: ^3.4.3`) removed the `valueOrNull` getter from `AsyncValue`; `value` itself is now nullable (`ValueT? get value`), so use `.value ?? fallback` instead - On this project's Riverpod 3.x, always read an `AsyncValue`'s data with the nullable `.value` getter, not `.valueOrNull` (that API is from Riverpod 2.x docs/muscle memory and no longer exists here).

[2026-09-22] - Project had package name / applicationId configured as `com.zymermusic.pencatatan_keuangan` instead of `com.zemetia.pencatatan_keuangan` - Renamed Kotlin directory structure from `com/zymermusic/` to `com/zemetia/`, updated `namespace` and `applicationId` in `android/app/build.gradle.kts`, `MainActivity.kt`, and all platform configurations (iOS, macOS, Linux, Windows) - All bundle identifiers and application IDs in this repository belong to the `com.zemetia` organization.

[2026-09-22] - Guessed Lucide icon names by analogy to other icon sets (`LucideIcons.check_circle_2`, `.bar_chart_3`, `.fingerprint`) when building the new Profile settings screens, and `flutter analyze` failed with `undefined_getter` for all three - The actual `flutter_lucide` names are `circle_check_big`, `chart_bar`, and `fingerprint_pattern` (verified by grepping `static const IconData` in the installed package at `<pub-cache>/hosted/pub.dev/flutter_lucide-<version>/lib/src/flutter_lucide.dart`) - Don't guess `flutter_lucide` icon names from memory of other icon libraries (Material Icons, FontAwesome); grep the installed package source for the exact identifier before using an icon you haven't already seen used elsewhere in this codebase.
