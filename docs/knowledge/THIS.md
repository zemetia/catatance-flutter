# Project Identity & Developer Style

## Project

Pencatatan Keuangan — a personal finance tracking app (Flutter, Android + iOS). Local-first: transactions, categories, and accounts stored on-device via Drift/SQLite. No backend/cloud sync in the initial scope.

## Developer preferences

- [2026-09-22] - Wants a fintech-modern visual style: smooth micro-animations, shimmer loading states, clean rounded UI — referenced `flutter_animate`, `fl_chart`, `flutter_slidable`, `shimmer`, `flex_color_scheme`, `google_fonts` explicitly as the desired stack.
- [2026-09-22] - Wants documentation structured like the `Zemetiash` Next.js project: a root `CLAUDE.md` pointing to `docs/blueprint/*` (architecture reference) and `docs/knowledge/{THIS,LEARN}.md` (living knowledge system) — this file and its siblings are the Flutter adaptation of that pattern.
- [2026-09-22] - Comfortable with Indonesian in chat; code, comments, and docs stay in English per this project's convention (matches Zemetiash).
- [2026-09-22] - Organization prefix & bundle ID / Application ID is `com.zemetia` (e.g. `com.zemetia.pencatatan_keuangan`), never `com.zymermusic`. All platform configurations (Android, iOS, macOS, Linux, Windows) must use `com.zemetia`.


## Insights

- [2026-09-22] - Currency is Rupiah (`id_ID` locale, no subunit in everyday use) — always format with `intl`'s `NumberFormat.currency(locale: 'id_ID', symbol: 'Rp ')` and store amounts as whole-Rupiah integers, never `double`.
- [2026-09-22] - `flex_color_scheme: ^9.0.0` requires the new standalone `material_ui`/`cupertino_ui` packages (SDK-decoupled Material), which conflicts with this Flutter SDK's own bundled `ThemeData` (`return_of_invalid_type` on `FlexThemeData.light()`/`.dark()`). Pinned to `flex_color_scheme: ^8.4.0` instead, which still returns `package:flutter/material.dart`'s `ThemeData`. Re-evaluate the 9.x upgrade once the installed Flutter SDK has fully adopted the decoupled Material/Cupertino packages.
- [2026-09-22] - Grouped settings/menu screens (e.g. `features/profile`) follow a reusable pattern: a `ProfileMenuSection(title, items: List<ProfileMenuItem>)` widget rendering one rounded `surfaceContainerHigh` card per section with divided `InkWell` rows — avoids repeating `ListTile` boilerplate per screen. Destinations that don't have a route/screen yet show a "segera hadir" `SnackBar` via a local `_comingSoon` helper instead of fabricating a `go_router` route, keeping `flutter analyze` clean until the real screen exists.
- [2026-09-22] - `FloatingNavBar` ([floating_nav_bar.dart](../../lib/core/widgets/floating_nav_bar/floating_nav_bar.dart)) wants a pronounced "floats above the screen" look, not a typical flush bottom nav: a fixed `AppSpacing.xl` gap from the bottom edge (never touching it), a large `28`px pill radius, and true glassmorphism via `ClipRRect` + `BackdropFilter(ImageFilter.blur(sigmaX/Y: 24))` over a `scheme.surface.withValues(alpha: 0.55–0.65)` fill plus a subtle 1px light-alpha border for the glass edge highlight. Selected tab uses a soft `scheme.primary.withValues(alpha: 0.14)` rounded pill behind the icon (Lucide has no filled/duotone variants, so state must be shown via color + this highlight, not a different icon glyph). Nav icons were deliberately swapped for more universally "modern" Lucide picks: `house` (not `layout_dashboard`) for home, `chart_spline` (not `chart_column`) for stats, `circle_user_round` (not plain `user_round`) for profile. ~~`piggy_bank` was kept for budget as the clearest signifier.~~ Budget tab icon changed to `wallet` per explicit user request (wanted a wallet glyph, not the piggy bank). ~~The center "+" FAB is intentionally raised further above the bar's top edge than a simple half-overlap (`_fabRaise = 10` on top of the `_fabSize/2` overlap, with `_barHeight = 74`) — user found the default half-sunk placement "agak kebawah" (felt too low); keep the FAB visibly poking up, not centered on the bar's edge.~~ Overcorrected: user then found that raised FAB "agak terlalu keatas" (too high) and asked for it bigger but lower. Current tuning: `_fabSize = 64` (bigger), `_fabPokeAbove = 22` — deliberately **less than half** of `_fabSize`, so most of the button sits embedded/sunk into the bar and only a modest cap pokes above its top edge. When adjusting this again, reason in terms of `_fabPokeAbove` (pixels poking above the bar's top edge) rather than an additive "raise" on top of a symmetric half-overlap — it's the more direct knob for "how much floats above vs. sinks into the bar."
- [2026-09-22] - The floating nav bar's glass panel itself was always transparent-by-design outside the pill (`Stack`/`SizedBox`/`SafeArea` have no fill) — the "kenapa bukan transparent, malah hitam" complaint was actually caused by each shell screen's own **nested** `Scaffold` (`DashboardScreen`, `ProfileScreen`, etc.) painting its full-height opaque `scaffoldBackgroundColor` (true black) behind the bar, combined with too little `ListView` bottom padding — the list content ended well above the bar, so there was nothing there to show/blur, just flat opaque scaffold black. Fix: `FloatingNavBar.clearance` (`= _bottomGap + _barHeight + AppSpacing.md`) is now the canonical bottom-padding value every scrollable screen under `AppShell` should use on its last padding edge, so content actually extends behind the glass (visible through the blur) instead of leaving a dead gap, and so the last list item isn't hidden under the opaque pill. Apply this to any new scrollable screen added under the shell. ~~True glassmorphism via `scheme.surface.withValues(alpha: 0.55–0.65)` fill~~ — even after the `clearance` fix made content actually scroll behind the bar, the glass still read as solid opaque black and appeared to "block"/hide list items (`ProfileMenuSection` cards) scrolled behind it, because on this `darkIsTrueBlack` theme a 0.65-alpha `surfaceContainerHigh` tint over blurred near-black content is still ≈black — there's no headroom for blurred content to show through. Fixed by lowering the fill to `alpha: 0.38` (dark) / `0.55` (light) and bumping the border to `alpha: 0.2` (dark) for definition — now blurred list-item text/shapes are visibly legible through the pill instead of vanishing into it. On a true-black theme, glass fill alpha needs to stay well under ~0.5 or it stops reading as translucent at all.

The user explicitly declined `git checkout --` on the conflicting file as a resolution step even though a patch backup made it safe ("jangan di stash dan jangan git checkout") — when a `git stash pop` conflicts due to a concurrent session's edit, prefer retrying the plain pop over `git checkout`/discard-based resolution, and always ask before touching git state further rather than assuming a "safer-looking" workaround is welcome.
